## 2026-10-19 首帧查询锚定与双向身份一致性 CPU 诊断

### 信息边界与对照

- 首帧位置使用缓存最初提供的 `query_uv`，不是用逐帧 GT 位置替换历史输入。它与 benchmark 的 GT 首帧位置相等是查询初始化约定，不是新模型取得的精度。
- 只使用已观测的 16 帧 RGB 与历史 UV/有效性，分别计算：首帧查询向前 LK、从该前向末点反向 LK、从 D4RT 末帧锚点反向 LK。所有往返检查仅覆盖历史，不使用真实未来。

- TAU 全部冻结，只做一轮 hidden/skip 输入特征修正；平均 RGB 修改上限 0.002、单像素上限 0.03。每片段额外向下匹配所有非零分支的实际修改量，零支持保留 keep，不放大修改。

## 2026-10-19 首帧采样 × 未来端点交叉：端点错误与目标偏差

本轮已完成 CPU 上 4 片段 ×9 分支，TAU 权重逐 tensor 验证未变；没有正式训练、参数拟合、阈值搜索或根据 GT 选择动作。代码为 `run_cross_objective_cpu.py`、`cross_objective_cpu.py`；本地结果 `cross_objective_results/`，服务器 `/root/autodl-fs/d4rt_training/cpu_first_query_cross_objective_20261019`。仍是同一批复用验证片段上的探索性诊断，不是独立测试集结论。

### 交叉合同与标签边界

历史采样 D=原 D4RT UV，L=首帧查询锚定、最多移动 2 px，F=完整首帧前向 LK；未来落点 P=冻结轨迹预测 UV，G=raw GT/Oracle UV。六个主分支为 D_P/L_P/F_P/D_G/L_G/F_G。

全部特征分支使用相同的点 ID、历史时间掩码、置信度/时间权重、未来点×时间写入掩码和可靠性权重。历史掩码为首帧往返掩码与 GT 历史可见性/边界及所有历史采样位置边界的交集；未来为 GT 可见性/边界、预测 UV 边界及至少3个共有历史观测的交集。**GT 共同掩码是显式诊断控制，因此本轮 P 分支也不是可部署推断评测。**匹配的是同一组点/时间；P/G 的实际空间落点不同正是被检验变量，不是把两者强行写在相同像素。

四例共享历史样本数为 376/135/1283/864，未来有效写入数为 160/72/643/258。历史样本数与上轮同支持 GT 采样误差评测一致。所有分支从同一个 H0/S0 出发做一次修正，不串联迭代。特征步长 0.002、元素 cap 0.05，RGB 平均 L1 上限 0.002、单像素 cap 0.03。每例将九分支向下匹配到相同实际 RGB L1，平均约 0.0004428；不放大输出，也没有在 evaluation 上选择步长。

三项额外控制均依赖标签，不能部署：H_G 用 GT 历史采样但保留相同历史汇聚；T_G 用真实未来编码特征作为目标；RGB_GT 用真实未来全图 MSE 的梯度作方向/可行性参考。RGB_GT 的监督范围与稀疏特征损失不同，不能当作公平可用的算法竞品，更不能把其收益作为方法效果。

animal3 不应混入“历史已经修好”的例子：上轮已经确认它的 LK 采样坐标和外观反而更差。本轮汇聚历史目标相对真实未来特征的误差 D=0.716、L=0.885、F=1.008，也明确变差；即使 Oracle 端点也不会自动纠正这个错误历史目标。GT 历史采样将该目标误差降至 0.274，说明它仍有实质历史采样错误。

### 结果二：特征损失不是最终 MSE 的等价目标，但没有普遍梯度反向

8 个特征分支 ×4 片段的特征目标全部下降，仍不能保证最终 MSE 或相对另一采样分支的 MSE 变好。实际受限隐特征修正方向与真实 RGB-MSE 下降方向的平均 cosine：L_P 0.0295、L_G 0.0681、H_G 0.0895、T_G 0.1339，RGB_GT 参考为 0.9609。

36 个实际隐特征修正方向的全局 cosine 均为正，实际像素变化的一阶 MSE 项也全部为负。因此本轮**没有证据支持“特征目标通常把全局梯度完全推反”**；更准确的解释是：部分历史目标/落点不匹配使 RGB 下降方向很弱，且特征目标改善不保持 MSE 的收益排序。

即使 GT 历史采样、Oracle 未来端点都正确，历史时间加权记忆仍不等于真实未来外观/编码特征：H 的目标误差在四例均非零；改为 T_G 后最终 MSE 在 4/4 片段进一步改善。这支持“固定历史汇聚目标存在时变外观/表示目标不匹配”，但不能仅凭本轮认定具体是光照、视角、形变或某一层特征造成的，也不能称为严格统计无偏性证明。

T_G 和 RGB_GT 都在 4/4 改善最终 MSE，说明冻结修正接口在这四例不是完全无法利用改善方向；但真未来目标和 RGB 梯度依赖未来标签，不是可部署解决方案。更不能据此跳过身份/可见性问题而直接训练更大模块。

### 结果三：还存在明确的有限修正幅度效应

按实际输出而非潜变量近似，独立计算精确恒等式：

`MSE(Y0+delta)-MSE(Y0) = mean(2*(Y0-GT)*delta) + mean(delta^2)`。

ds 例 L_P 的特征损失下降 0.0423，但 MSE 相对 TAU 增加约 3.627e-6：方向项 −3.818e-6，平方代价 +7.445e-6。animal3 的 L_G 也有同类情形：方向项 −1.092e-6、平方项 +4.092e-6，合计 MSE 增加约 3.000e-6。对这些输出方向，存在更小的输出残差幅度能避免损害；不能把 harm 全归为位置或“梯度反向”。

匹配平均 L1 不等于匹配平方 L2，不同方向的空间集中程度仍不同。另作仅算术、事后、未参与决策的共同 L2 替代匹配后，局部历史修正在预测 UV 下四例仍都损害 MSE，在 Oracle UV 下仍是三例改善、animal3 变差。因此主要反转不是单由 L2 不同造成。

`diagnostic_summary.json` 还提供事后 alpha=0.25 的固定输出残差插值敏感性，直接由上述恒等式计算 MSE，没有重新优化潜变量、没有挑选动作，也没有评测相应 LPIPS。它不是预注册策略或最优步长，不能用来宣称泛化改进，更不能在部署时用未来 GT 选择 alpha。

### 本轮归因与后续边界

在这四例内：三例的历史收益被预测端点错误阻断；一个反例的历史采样本身未修好；此外历史目标与真实未来特征仍不匹配，弱 RGB 对齐方向在固定归一化步长/修改预算下会产生有限步长损害。这些因素存在交互，不能做全局加性百分比分摊。

若继续低成本工作，应优先在不读取真实未来的历史回放中校准修正幅度与 accept/keep，检查身份错误片段，并把未来端点可靠性和收益风险分开评估；不是直接解冻 TAU、扩大写入幅度或启动正式训练。需要独立前缀 D4RT 缓存的回放仍不能用完整历史缓存切片替代。本轮未实施这些下一步策略。

7 项新单元测试通过；`verify_cross_objective_results.py` 独立验证源码哈希、每分支实际 L1、四格差分/交互项、逐分支与成对输出的 MSE 精确分解、均值及冻结权重标记。主结果保存 raw 和 matched 两套指标、每例全部损失/方向诊断、共同掩码与权重张量；没有删除旧结果、改变 checkpoint 或启动训练。

### 任务边界与信息隔离

严格前缀 D4RT XYZ/UV 缓存仍缺失。因此本轮使用从当前前缀 RGB 独立重算的首帧角点/LK，比较保持最后位置和稳健恒速，不声称校准了原来的 D4RT 轨迹预测器。没有用完整16帧 D4RT 或 TAU 隐特征缓存切出短前缀，没有读取轨迹 GT、可见性 GT 或 teacher 数组。

逐片段执行以下顺序，每个阶段独立进程：

1. 只解码帧0:8，重算 TAU、历史跟踪和候选，锁定输出后才解码已观测的8:12作回放校准。
2. 只用帧0:12重算新的基线与候选，锁定后才解码已观测的12:16作独立后段检验。该后段只允许接受/拒绝第一段选定的配置，不重新挑另一个配置。
3. 用帧0:16重算真正推断候选，锁定最终动作。只有全部6个片段都锁定决策后，统一评测进程才允许解码帧16:24，真正未来指标从不参与选择。

历史回放窗口只覆盖4步，因此只修改最终预测的前4帧；第5–8帧像素逐位保持原 TAU。短前缀不足 TAU 所需16帧时左侧重复首帧；这是明确的输入分布偏移，不能把回放通过解释成未来安全保证。

所有空间编码、时序预测和隐特征都由当前前缀重算。跨阶段仅传递较早前缀生成的点×horizon布尔可用掩码和已观测 RGB 上的校准结果，且验证帧重叠部分的字节哈希与首帧种子哈希；不传递全上下文隐特征。后续可用掩码只能缩小，不能添加前段未检验的轨迹/时刻。

### 固定规则与对照

未来端点可靠性来自当前前缀内部4步运动回放，以连续且未失效的 LK 位置作观测参考；它不是 GT 轨迹或未来正确概率。逐步循环误差 ≤1 px、全局回环差 ≤2 px、局部纹理标准差 >0.02，并要求对应运动模型的内部回放误差 ≤2 px。失效轨迹不恢复。

对保持位置/恒速各生成一次冻结特征修正方向，再用 alpha={0.125,0.25,0.5} 缩放受限输出残差。校准要求全图 MSE 改善超过 max(1e-8,基线MSE×1e-4)，LPIPS 改善超过1e-5；优先最小通过幅度，再比较 LPIPS/MSE。独立后段必须再次通过同样双指标门槛，否则 keep。所有规则在打开本轮真正未来帧前固定，没有据未来效果放宽阈值。

特征归一化步长上限0.002、元素cap0.05；缩放前前4帧 RGB 平均L1上限0.002、逐像素cap0.03，缩放后分别最多0.001和0.015。实际修改量逐例保存；不同策略的修改量不强行相等，因为幅度选择与 keep 本身就是被检验的策略行为，不能把不同幅度下的差异全部归因为端点掩码。

对照包括：原 TAU/keep、固定有端点可靠性门控的 CV alpha=0.25、去端点可靠性门控的 CV alpha=0.25、仅第一段校准而不作第二段图像指标拒绝，以及完整校准策略。所谓“去第二段拒绝”仍使用相同历史几何支持传递，只移除 MSE/LPIPS 接受条件。

8/12/16帧RGB前缀与TAU隐特征分别从头重算；不读旧全上下文隐特征，不切片16帧D4RT缓存作8帧回放。两段历史RGB校准后支持只能缩小。只有最终16帧D4RT分支允许读取白名单query_uv/past_xyz/past_uv/past_valid/past_confidence，不加载teacher/future数组作为输入。每个片段全部56个正常输出及动作记录落盘锁定并哈希后，才进行该片段真实未来评测；Oracle诊断后再次核验正常输出哈希未变。

与CPU六例实验不同，本轮采用**固定代码、逐片段输出锁定后评测**，而非先在磁盘保存全1489片段预测再统一打开未来GT。指标结果不传回生成函数、不更新跨片段状态、动作或参数；协议/权重/实现哈希预先锁定。NPZ压缩数组底层可能整块读取；隔离保证是生成函数只收到当前前缀张量，不声称底层文件从未含有未来字节。

历史纹理/scorer/传播融合保留原来的fp16输入/预测量化边界，并对自己的量化基线报告增量，另保留共享FP32基线；本次所有方法采用同一FP32未来标签，因此旧报告的绝对值（旧标签亦fp16）不保证逐位相同。共同预算上限不等于实际修改量相同，只有明确matched分支作实际预算匹配。

### 审计已发现的限制

`audit_full_gpu_leakage.py` 已确认近期pilot fit/dev/calibration原视频与test无交集。Omega多seed训练使用随seed变化的旧子集划分：统一347测试片段中，seed42/123/3407分别有0/27/20片段曾被对应适配器训练。结果保留但标记曝光；`report_full_gpu.py` 另剔除对应适配器及64主干train/val原视频，报告各seed未曝光子集及共同交集，不能直接把统一test三seed平均作为独立测试。

D4RT缓存生成源码确实分别执行context-only和full teacher；past字段来自context-only，teacher/Sim3对齐仅产生未来标签。但首帧query来自GT可见性/UV及有限深度，是benchmark提供的特权查询初始化，不是纯RGB端到端系统。原combined_splits还以future_valid.any()筛选可用PO片段；这是继承的数据资格选择偏差，不是本轮推断使用未来GT，仍需披露。Omega缓存依据manifest、生成源码、形状/有限性及字节哈希审计，并非独立重算基础模型后证明缓存绝对无泄漏。
