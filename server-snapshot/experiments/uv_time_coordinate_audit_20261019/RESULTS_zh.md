# 预测 UV 时间、归一化与冻结 RGB 注入排查

2026-10-19。已完成主对照。没有正式训练、参数拟合或优化器步骤，TAU 和轨迹预测器逐 tensor 权重检查保持不变。

## 结论

预测 UV **并非完全没有收益**：平均轨迹误差优于保持最后位置，注入后也改善一部分 MSE。但它距离 Oracle 仍远，且 LPIPS 变差，开发集选择 keep 有依据。

当前没有发现统一的 x/y 互换、取值范围、W/H 归一化或整体首帧索引错误。主要证据指向：历史锚点与速度有误差，远期预测误差累积，逐点残差不稳定；错误对应进入历史外观传输后产生感知质量代价。位移不足/方向偏差有迹象，但尚不能确诊为统一的运动相位滞后。

历史末尾缺失时的 elapsed-time 问题确实存在，但涉及约 3.5% 的所选轨迹，不是主差距的充分解释。修正最后位置一个因素也不足以把 Oracle 的多项收益兑现。

## 1. 范围与接口

- 复用既有 dev12、validation40，每原始视频一个片段，视频等权；不是完整数据集或独立新测试。
- 不读取 test/TUM；没有在 validation 上选择幅度、阈值或新策略。
- 固定沿用 v2 一次隐特征修正：历史外观目标、步幅 0.002、hidden/skip 单元素修正上限 0.05；最终 RGB 均值绝对修改 ≤0.002、逐像素修改 ≤0.03。
- 相同历史点筛选、历史 confidence、历史记忆、冻结编码器/解码器，仅替换未来 UV。
- 分别运行未来 GT 可见性诊断与未知可见性（仅过滤有限/图内 UV）两套接口。
- 另逐视频、逐可见性接口匹配实际 RGB 修改量，所有分支只缩小到该组最小修改量，不放大任何分支。Oracle/观察 GT 参与的预算匹配也仅为诊断，不是部署策略。
- “观察 GT 重锚定”“GT 历史恒速”“Oracle”均单独标记为标注依赖诊断，不能与普通可部署输入混称。

## 2. 时间索引

代码链条为：源片段的历史 RGB/轨迹 `0:16`，未来 RGB/标签 `16:24`；D4RT 查询的历史目标索引是 `0..15`；预测器输出 8 个 UV，对应未来步长 `1..8`。当前没有找到把未来第 0 槽当作历史最后一帧的代码。

冻结预测器重新前向后与既有缓存预测逐点一致；同时用 head 输出重构 `anchor + velocity × step + residual`，裁剪后与前向结果一致。训练代码与推理代码都使用默认 residual_scale=0.08；checkpoint 未显式保存这个标量是可复现性隐患，但本次没有发现数值不一致。

条件性问题：模型 anchor 使用最后有效历史位置。如果最后有效时刻为 j<15，几何上应外推 `16+k-j` 步；当前模型的恒速基线仍只用 `k+1` 步。诊断实现了补偿间隔的恒速方法，但没有修改生产预测器或重训。

所选轨迹中，末尾缺失比例视频等权约 3.48%，平均 age=0.250 帧；最近四段没有有效相邻速度的比例约 2.28%。轨迹计数为：末尾有效 4831 条、缺 1–3 帧 60 条、缺 ≥4 帧 92 条。视频等权比例与全体轨迹直接计数比例不同。

即使末尾有效的轨迹，预测 ADE 仍约 7.02 px；缺 ≥4 帧的子群约 18.11 px，是值得单独处理的困难子群，但不能代表主要样本。

时间 lag 探针中，预测与较早一帧真值更近，并不自动证明代码错一帧：较早目标也通常更靠近历史位置。补充机制统计中，保持位置和恒速也出现这个现象。在可可靠恢复点序的补充子集上，把输出前移一槽并线性外推末槽，ADE 只改善约 0.059 px，CI `[-0.183, +0.056]` 跨零，没有支持统一“一帧修复”。该探针没有进入 RGB 策略。

补充子集相同裁剪下，elapsed-gap 恒速相对原恒速 ADE 差 +0.00294 px，CI `[-0.00104, +0.00952]`，没有确认总体改善。这不否定条件性时间间隔的语义问题，但不支持把它当作当前主瓶颈。

## 3. 坐标归一化与边界

源标签使用 `u/(W-1), v/(H-1)`；D4RT query 的 `2u-1, 2v-1` 网格及本轮采样使用 align_corners 语义，与此约定一致。输出仍是归一化 UV，训练 RGB 使用 64、当前 RGB 使用 128，不需要再把 UV 乘二。

40 视频的归一化假设探针：

| 假设 | UV ADE，128×128 像素单位 |
|---|---:|
| 原约定 | 7.3234 |
| 改按 W/H 而非 W−1/H−1 | 7.3480 |
| x/y 互换 | 49.0171 |
| 误当作 [-1,1] 再转换 | 48.1474 |
| 误当作 128 分辨率像素再除 127 | 93.4696 |

W 与 W−1 的差异带来的预测位置改变量均值约 0.146 px、视频均值最大约 0.240 px，无法解释约 7 px 的主要差距。

约 1.64% 的预测点—时刻触发模型内部 [0,1] 裁剪；取消裁剪后 ADE 从 7.3234 变为 7.3333，RGB 对照也没有解决差距。v2 保留原始 UV/边界过滤仍是正确接口，但单独取消预测器 clamp 不是有效补救。

## 4. 逐时刻误差

以下为未来物理可见、有限且在图内的相同 GT 掩码，所有方法使用同一批点；误差先在视频内平均，再对视频等权。单位是归一化 UV 欧氏距离乘 127。

| 方法 | t16 | t17 | t18 | t19 | t20 | t21 | t22 | t23 | ADE |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 预测器 | 4.59 | 5.20 | 6.01 | 6.65 | 7.64 | 8.75 | 9.80 | 10.44 | 7.32 |
| 保持最后有效位置 | 5.73 | 6.37 | 7.24 | 7.99 | 9.06 | 10.22 | 11.29 | 12.01 | 8.66 |
| 模型内稳健恒速、同样裁剪 | 5.26 | 5.61 | 6.36 | 7.11 | 8.18 | 9.33 | 10.46 | 11.28 | 7.89 |
| 稳健恒速 + elapsed gap，raw UV | 5.27 | 5.62 | 6.37 | 7.12 | 8.19 | 9.35 | 10.49 | 11.33 | 7.90 |
| 最近两次有效观测恒速，除以实际时间间隔 | 5.54 | 6.10 | 6.97 | 7.77 | 8.89 | 10.08 | 11.18 | 11.94 | 8.48 |

模型相对保持位置平均改善约 1.33 px，配对 95% CI `[0.21, 2.44]`（这里记作基线−模型，正为模型更好）。相对稳健恒速平均改善 0.56 px，但 CI `[-0.04, 1.13]` 跨零，不能宣称稳定胜过恒速。

最近两点恒速更差，说明简单利用最新速度容易放大历史轨迹噪声。不能从这组结果推导“去掉学习残差就能解决”。

注意：raw elapsed 恒速与 clipped 模型恒速同时存在 gap 和边界差异，不能把两者 ADE 差直接归因给 gap。补充机制文件单独提供相同裁剪下的 gap 对照。

## 5. 锚点、速度与学习残差

- 所选历史最后锚点相对源数据同点、同历史时刻 GT 的位置误差约 **5.43 px**。这是全部有限锚点的平均，不与未来可见掩码完全等同。
- 只把预测轨迹整体重锚到观察时刻的 GT 位置，保留模型预测位移，ADE 从 7.3234 降到 **6.1850 px**；配对变化 -1.1384 px，CI `[-2.0867, -0.1872]`。该分支使用观察 GT 标注，不是可直接部署的修复。
- GT 历史位置的恒速诊断 ADE **4.6350 px**，GT 历史保持位置 **5.5361 px**。可见历史观测/速度质量是实质限制；这不证明恒速在所有真实场景足够。
- 相对 D4RT 锚点的目标位移超过 2 px 时，预测位移模长平均约 6.21 px、目标约 11.93 px；沿目标方向的位移投影比约 0.366。它提示运动收缩/方向偏差，但这个口径含锚点误差，不能直接当作物体真实速度比。
- 学习残差平均每坐标绝对幅度约 2.21 px；约 **47.5%** 的可见点—时刻，在加入学习残差后比模型内部恒速基线更远。它能通过改善部分困难样本降低平均 ADE，却并非对所有点都可靠。

主文件的位移分桶是“未来 GT 相对 D4RT 锚点的位移”，不是纯真实运动分桶，不能将低位移桶直接称作静止物体。补充机制文件使用 GT 第 15 帧到未来的位移，并要求该历史 GT 可见，以避免混淆这两个概念。

| Oracle UV | 0.009623587 | 0.25757537 | 0.029913873 |

预测 UV 相对 TAU：

- MSE 差 -1.3101e-5，CI `[-2.1103e-5, -5.5374e-6]`，确有像素误差收益。
- LPIPS 差 **+0.00027025**，CI `[+0.00002971, +0.00053478]`，出现感知质量代价。
- 时序误差差 +1.7830e-6，CI 跨零。

同预算 Oracle 相对预测 UV 的 MSE 差 -3.1473e-5，CI `[-4.3152e-5, -2.0448e-5]`。GT 可见性接口下仍有同方向优势（约 -3.00e-5），所以不是单靠可见性标签或修改更多产生的差异。

保持最后位置的 LPIPS/时序均值较好，但 MSE 比预测 UV 明显更差，不能把它当作全面替代。恒速也没有带来多指标突破。**平均 UV ADE 的排序不能替代最终 RGB 多指标排序。**

只重锚使 UV 明显更准，却几乎没有改善 RGB：相对预测 UV 的 matched MSE 差约 -3.94e-7、CI 跨零。历史外观仍沿原 D4RT UV 采样，重锚没有修复这条采样路径；该现象与“历史对应/外观也需要处理”的解释一致，但不是对所有剩余误差原因的独立证明。

开发集在 keep 与固定 0.002 修正之间选择时，只有 Oracle 两个可见性分支选择编辑；预测 UV、保持位置、各恒速、取消裁剪和重锚分支均选择 keep。这里是开发集实际组合指标的取舍，不是局部评分器校准余量造成的全拒绝。

## 7. 额外发现的数据一致性问题

PointOdyssey 多数片段中，源 3D 投影 UV 与保存的 `tracks_uv_source` 差异约 0.01–0.09 px，但 `cab-h-bench-3rd-09c3ccd3_clip_000` 的未来可见点平均差为 **2.3938 px**（128 分辨率单位）。它不是全局 W/H 比例问题；具体标注/相机参数原因尚未确定。

已保存该片段及各 horizon 差异，**没有删除样本、改标签、重选评价集或据此调整阈值**。正式研究前应独立核查该数据问题。

## 8. CPU 补充统计的额外限制

旧缓存没有单独保存所选 query 索引，部分源点的 D4RT UV/置信度历史完全重复。GPU 不可用后，用历史签名及冻结 CPU 轨迹预测的一对一匹配恢复身份；5 个视频未满足严格匹配精度，另有 46 条子采样轨迹身份不唯一，未用于这份补充统计。补充机制描述因此只覆盖 35 个视频，不应与主 40 视频均值混用。

主 GPU 实验直接重建并验证原 top-k 顺序，**40 视频主 UV/RGB 对照完全未删样本**。补充跳过由身份恢复精度决定，不由预测效果决定；完整清单、误差和计数保存在 `mechanisms_summary.json`。后续缓存应显式保存 selected_query_ids、时间索引和归一化约定，避免这种恢复歧义。

## 9. 结论边界与下一步

本轮已经排除了几类粗接口错误，并确认“预测轨迹有一些 MSE 收益，但远未兑现 Oracle 的像素/时序优势，且损害 LPIPS”。不是一个 clamp 或一帧偏移开关就能解决。

下一步仍优先冻结诊断：

1. 将历史轨迹质量与未来运动误差分开，先检查后几帧锚点/速度的稳定性；不要仅给预测端整体加位移倍数。
2. 对失效末尾轨迹显式记录 last_valid_time、速度估计时间间隔和无速度回退；当前只做了对照，没有改生产模型。
3. 区分未来端点修复与历史外观采样修复，用同一批点、同一 RGB 修改量检验两者是否互补。
4. 继续保留保持位置/稳健恒速以及 keep，按区域/轨迹可靠性分析，而不是把所有点都交给学习残差。
5. 评价同时看 MSE、LPIPS、时序；不要用更低 ADE 或特征一致性 loss 代替收益兑现。

主实验约 63 秒模型计算，15 项单元/集成测试通过，`verify_uv_audit.py` 已独立重算 UV ADE、8 个 horizon、RGB 均值、实际预算匹配、开发集选择与配对比较。TAU 和轨迹预测器权重均保持逐 tensor 一致。

主体 GPU 对照完成后，服务器 GPU 接口变为不可用，补充机制统计改用 CPU；没有安装驱动、修改环境或启动训练。所有结果属于复用样本上的探索性诊断，bootstrap CI 未进行多重比较修正。
