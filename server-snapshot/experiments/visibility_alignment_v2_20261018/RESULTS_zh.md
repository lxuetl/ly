# 可见性接口修正与冻结表示对齐对照

2026-10-18，westb:34220。已完成；没有正式训练、没有参数拟合、没有优化器步骤，模型权重保持不变。

## 一、回答当前问题

**Oracle 轨迹的收益现在可以进入最终 RGB 预测，但目前只确认了探索性样本上的 MSE 和时序误差收益，不能宣称整体指标改善或可部署分支已经成功。**

修正可见性后继续用原适配器，仍几乎没有 MSE 收益。改为冻结编码器/解码器一致的特征目标后，Oracle 分支 MSE 相对 TAU 下降约 0.49%；均匀历史聚合分支约 0.61%。实际图像修改量匹配之后，Oracle 相对预测 UV、固定位置记忆和打乱轨迹对应的 MSE 优势仍保留。双方都不使用未来真实可见性时，Oracle UV 优势也保留。

但是 LPIPS 没有可靠改善；预测轨迹分支的开发集最优选择仍为 keep。不能因此启动正式训练。

## 二、接口做了什么修改

`forecasting/video_forecast_dataset.py` 新增显式 v2 选项：

```python
VideoForecastDataset(..., explicit_trajectory_interface=True)
```

该路径保留原始、未裁剪的源数据 UV，并分离：

- `future_uv_raw`：未来真实 UV，可能越界或非有限，不能裁到边缘后写入。
- `future_visibility_gt` / `future_in_bounds`：物理可见性与图像内有效性分开。
- `future_visibility_d4rt_teacher` / `future_valid_d4rt_teacher`：D4RT full-clip teacher 可见性与包含其他有效性条件的掩码分开，均不是物理 GT 的替代品。
- 历史 GT UV、可见性、图内掩码及组合有效性也分别提供，仅供 Oracle 诊断。

历史 confidence 仍只作为历史传输可靠性权重，不宣称它是未来可见概率。

`visibility_interface.future_gate` 强制声明 `unknown`、`predicted` 或 `oracle_gt` 来源；使用 GT 必须显式开启 Oracle 诊断。未知可见性不接收伪装成概率的张量，只使用有限/图内条件作为写入资格。

`TrackCrossAttention.forward` 增加未来可见性门控，按每个点、每个预测时刻在 splat 前过滤。采样、特征和置信度中的非有限值也有明确回退，不再出现 NaN×0 污染。历史无效或未来不可写时回退 identity。

**兼容范围：**本轮 v2 对照已使用修正接口；旧 Dataset 默认行为保留，以便重现既有实验。旧缓存未覆盖，旧训练脚本也未自动迁移。后续若正式训练，必须显式切换并审计原始 UV/可见性来源，不能直接假定旧脚本已经修好。

服务器旧源文件备份保留为 `.pre_visibility_v2`。没有改写旧模型或旧结果。

## 三、表示对齐：没有训练新映射

此前是把历史 encoder 特征投影后直接加到未来 translator hidden，两个表示空间不保证兼容。

本轮采用单次**隐特征优化**作为无参数拟合的对照，不是更新模型权重：

1. 使用相同冻结编码器提取观察帧外观和 TAU 预测 RGB 的外观。
2. 沿历史轨迹采样外观，再聚合为每个点的历史记忆。
3. 在未来 UV 上比较预测外观与历史记忆，形成稀疏、带可见性/可靠性权重的特征一致性损失。
4. 通过冻结编码器和解码器，把该损失的梯度传到 hidden/skip 输入；仅做一次固定步幅修正，再生成最终 RGB。
5. 最后统一施加平均绝对图像修改量 ≤0.002、逐像素修改 ≤0.03 的限制。

正常历史记忆分支的优化目标不使用未来 RGB。`aligned_true_appearance` 是单独标注的未来真实外观诊断，不能部署，也不能当成普通方法收益。

隐特征步幅预设为 0.002/0.02，单元素隐特征修正限制 0.05；开发集选择包含 keep。原始特征替换、未对齐 residual 和仅 hidden 的对齐分支都保留，用于区分不同路径。不同方法的步幅单位和实际 RGB 修改量并不天然相同，不能只凭同一步幅宣称纯表示因素的独立因果贡献。

## 四、数据与选择协议

- 既有开发集 12 个原始视频，每视频一个片段；确定幅度时不看评价结果。
- 既有验证集 40 个原始视频，每视频一个片段，视频等权。
- 保留两档固定非零步幅的所有验证结果；主结果使用开发集选定的系数，不在验证集重新挑选。
- 轨迹 UV 对照共享同一历史轨迹筛选、历史置信度和未来 GT 可见性；另有两边都不使用未来 GT 可见性的对照。
- 均匀历史分支保留相同历史 confidence，只去掉指数时间衰减；固定位置分支在同一个未来端点上检索各历史帧，写入端点与轨迹分支相同。
- 没有使用 test/TUM。开发集和验证集均已在此前探索中使用，不是独立确认样本。

下表为开发集选定系数后的 40 视频结果，MSE/LPIPS/时序误差均越低越好。

| 未对齐的 encoder residual → hidden | 0.009667936 | 0.25749564 | 0.029936538 |
| 对齐目标，仅修正 hidden，Oracle UV | 0.009646083 | 0.25753298 | 0.029922514 |
| 对齐目标，修正 hidden+skip，Oracle UV | 0.009621137 | 0.25760242 | 0.029916369 |
| 同上，均匀历史聚合 | 0.009609186 | 0.25758663 | 0.029903780 |
| 预测 UV + 真实可见性，开发集选择 keep | 0.009668161 | 0.25749244 | 0.029936624 |

主要 Oracle 对齐分支相对 TAU：

- MSE 差 -4.7024e-5，原视频配对 bootstrap 95% CI `[-6.1907e-5, -3.3439e-5]`，相对下降约 0.49%。
- 时序误差差 -2.0255e-5，CI `[-3.6946e-5, -4.9220e-6]`。
- LPIPS 差 **+0.0001100**，CI `[-0.0001997, +0.0004541]`：不能证明改善，也不能据 CI 跨零宣称已证明非劣。

均匀历史分支 MSE 下降约 0.61%，LPIPS 均值仍略差、CI 跨零。当前无需增加复杂时间注意力，简单聚合仍是必须保留的基线。

## 六、是否只是图像修改量不同

补充固定 0.002 步幅的归因对照：每个视频取六个分支实际 RGB 修改量的最小值，所有分支只向下缩放到相同修改量，不放大任何分支。平均实际修改量为 0.000690891。该预算依赖 Oracle 分支，是诊断控制，不是可部署策略。

| 等实际修改量分支 | MSE | LPIPS | 时序误差 |
|---|---:|---:|---:|
| Oracle UV + GT 可见性 | 0.009624955 | 0.25759062 | 0.029916952 |
| 预测 UV + 同一 GT 可见性 | 0.009655236 | 0.25774275 | 0.029943308 |
| 固定位置记忆 + Oracle UV/GT 可见性 | 0.009676030 | 0.25737760 | 0.029947458 |
| 打乱轨迹记忆对应 + Oracle UV/GT 可见性 | 0.009654472 | 0.25799358 | 0.029951494 |
| Oracle UV + 未知可见性 | 0.009624832 | 0.25758243 | 0.029914198 |
| 预测 UV + 未知可见性 | 0.009655479 | 0.25774872 | 0.029937424 |

Oracle UV + GT 可见性，相对：

- 预测 UV：MSE 差 -3.0281e-5，CI `[-4.2643e-5, -1.8978e-5]`。
- 固定位置：MSE 差 -5.1075e-5，CI `[-7.0500e-5, -3.2920e-5]`。
- 打乱轨迹对应：MSE 差 -2.9517e-5，CI `[-4.0536e-5, -1.9594e-5]`。

两边都不使用未来真实可见性时，Oracle UV 相对预测 UV 的 MSE 差为 -3.0648e-5，CI `[-4.2340e-5, -1.9810e-5]`。因此差异不只是 GT 可见性信息或修改更多产生的。

GT 可见性相对未知可见性在当前匹配预算下没有 MSE 优势，差 +1.24e-7、CI 跨零；不能通过这组结果声称可见性预测已经解决。接口修正的价值首先是语义正确、避免错误边界写入，而不是保证平均指标立即上升。

补充对照是看过主结果后进行的归因分析；CI 未做多重比较修正，且仍使用旧验证数据，不能提升为独立确认结论。

## 七、还卡在哪里

1. **轨迹有用，但预测 UV 尚未把优势兑现为多指标收益。**固定 0.002 的预测 UV/未知可见性分支相对 TAU 虽改善 MSE约 1.34e-5，但 LPIPS 差 +0.000306，其 CI `[+0.0000470, +0.0005868]`；开发集选择 keep 有实际依据。
2. **历史外观一致性不是最终预测质量的充分目标。**Oracle 与预测分支的特征目标都在 40/40 视频下降；主要 Oracle 分支平均 after/before 约 0.810，预测未知可见性约 0.817，但最终指标不同。不能用特征 loss 下降替代 RGB 评测。
3. **更真实的外观仍有空间，但不是当前可部署信息。**未来真实外观诊断进一步降低 MSE；后续应处理历史采样漂移、遮挡和外观随时间变化，而不是把未来 RGB 标签混入普通分支。
4. **提升不是“学会了更强的 attention”。**本轮没有训练注意力，均匀聚合反而更好；结果仅证明借助冻结模型的一致表示目标，可以让轨迹对应的价值进入最终像素预测。
