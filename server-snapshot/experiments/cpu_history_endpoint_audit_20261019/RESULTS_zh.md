# CPU 审查：历史外观采样错误与未来端点错误

日期：2026-10-19。已完成本地缓存分析、40 视频 CPU 采样审查和 3 个代表片段的冻结模型交叉对照。没有正式训练、参数拟合或模型权重更新。

## 结论

**两端都有实质错误，而且存在交互作用，不是只修历史或只修未来 UV 就必然解决。**

历史 GT 采样能明显改善外观记忆，但如果未来端点仍错，改善后的外观可能被施加到错误位置。在 3 个代表片段中：

- 保持预测端点，仅修历史采样，MSE 全部变差；LPIPS 有好有坏。
- 固定 Oracle 端点，仅修历史采样，MSE、LPIPS、时序误差全部改善。
- 因此“历史特征更接近真实外观”与“最终预测更好”之间，仍需要可靠的未来对应关系。

这是对冻结修正路径的局部因果对照，不是论文级泛化结论，也不是用 GT 改善后即可部署。

## 1. 已有缓存告诉了什么

复用上轮实际 RGB 修改量匹配后的 40 视频结果，未重选验证集、未改阈值：

| 现象 | 视频数 |
|---|---:|
| 预测 UV 注入改善 MSE | 28/40 |
| 改善 MSE、同时损害 LPIPS | 20/40 |
| 同时改善 MSE 和 LPIPS | 8/40 |
| Oracle UV 比预测 UV 的 MSE 更好 | 34/40 |
| 观察 GT 重锚使 UV 更准 | 30/40 |
| 重锚后 UV 更准、RGB MSE 却未改善 | 12/40 |
| 历史特征一致性 loss 下降 | 40/40 |

这说明：未来位置确实重要，但 UV ADE、最后锚点误差或特征一致性 loss 都不能单独替代最终 RGB 评测。

最后锚点误差与 LPIPS 代价的跨视频相关系数仅约 0.058，不证明历史端无关：最后一个位置并不等价于整段历史的外观采样污染。该统计是回顾性相关，不是因果估计。

## 2. 40 视频 CPU 采样审查

不需要 GPU 或解码器梯度。直接从真实历史/未来 RGB 按点采样，使用新建、稳定的 CPU 历史评分 top128，保存原始 query 索引，不再猜测旧 CUDA top-k 的重复点顺序。

历史坐标比较使用相同掩码：D4RT 历史有效、两套位置有限且在图内、GT 历史可见。时间衰减与历史 confidence 完全相同。GT 只用于诊断参考，不用于可部署策略。

| 指标 | 视频等权均值 |
|---|---:|
| 有效历史 D4RT 对 GT 位置误差 | 2.14 px |
| 最后历史帧位置误差 | 4.43 px |
| 同一历史帧，D4RT/GT 两处采样的 RGB MAE | 0.05421 |
| D4RT 历史记忆 → 真实未来点颜色的 MAE | 0.07761 |
| GT 历史位置采样记忆 → 同一真实未来颜色的 MAE | 0.03302 |
| D4RT 自有历史掩码下的记忆 → 真实未来颜色 MAE | 0.07842 |
| 同一未来帧，预测端点/GT 端点采样颜色的 MAE | 0.10172 |

仅替换历史采样位置，历史记忆与未来真实颜色的 MAE 下降约 **57%**，40/40 视频均下降。仅改善历史可见性过滤的平均颜色误差变化较小，不能将这 57% 的差异解释成“只是掩码更严格”。

未来端点的颜色误差也很明显，独立于历史记忆构造，说明写入位置确实可能对应到错误外观。

这两种 MAE 的统计对象不同：一个是历史多帧聚合，另一个是同一未来图像上的两位置采样。**不能直接按 0.10172 与 0.07761 大小判定哪端更重要。**

本轮 2.14/4.43 px 与上轮锚点指标口径不同：新 CPU 点序、有效性交集、历史全部/末帧分别统计，因此不能解释为轨迹预测器自动变好了。源数据中此前标记的 UV 标注异常也未删除。

## 3. 少量冻结模型的交叉对照

### 设计

符号：D 为 D4RT 历史采样，G 为 GT 历史采样；P 为预测未来端点，G 为 GT 未来端点。

| 分支 | 历史外观采样 | 未来端点 |
|---|---|---|
| D_P | D4RT | 预测 |
| G_P | GT | 预测 |
| D_G | D4RT | Oracle |
| G_G | GT | Oracle |

四格共享点身份、历史有效性、历史 confidence、时间聚合、未来有效点及写入权重。仅改变采样坐标或未来端点。额外保留“仅改变历史掩码”和“未来真实外观参考”分支，防止混淆掩码、外观和几何贡献。

TAU、轨迹预测器和编码器全冻结。使用相同的特征一致性目标，仅对 hidden/skip 输入做一次步幅 0.002 的修正，单元素限幅 0.05；最终 RGB 修改均值上限 0.002、逐像素上限 0.03。每片段再将六个分支向下缩放到相同实际 RGB 修改量，并保留未匹配的原始结果。

选择的是旧结果中的感知失败、Oracle 差距最大、正向对照三类片段，不是独立或随机验证样本。原先准备 6 个案例，但 CPU 实际配额为半核/2GB，最终采用单线程独立进程完成 3 个预定角色的案例，未根据新交叉对照的好坏挑选。

### 历史采样修正的条件效应

下表的 ΔMSE 为“历史 GT 采样 − 历史 D4RT 采样”，负数为改善；每行都匹配实际图像修改量。

| 片段 | 预测端点下修历史 ΔMSE | Oracle 端点下修历史 ΔMSE |
|---|---:|---:|
| dancingroom1_3rd2，感知失败 | +2.09e-6 | −1.11e-5 |
| clean_seq138，端点差距大 | +1.22e-5 | −7.88e-6 |
| decoration_skeleton_seq139，原有正向对照 | +7.29e-5 | −2.55e-5 |

3 个片段中，GT 历史采样也都降低了编码器空间的历史记忆误差：分别约从 0.788→0.427、0.211→0.134、0.210→0.0358。这不是单纯颜色代理指标才出现的现象。

但位置更准确、记忆更准确，仍不能保证在错误端点下输出更好。该控制直接补上了上轮“只校正锚点却没有 RGB 收益”留下的疑问。

### 三案例均值，仅用于描述

每个案例内修改量相同，跨案例平均实际 RGB 修改量约 0.0006508：

| 分支 | MSE | LPIPS | 时序误差 |
|---|---:|---:|---:|
| 原 TAU | 0.009400791 | 0.23728985 | 0.037519647 |
| D_P | 0.009383695 | 0.23801414 | 0.037512729 |
| G_P：只修历史采样 | 0.009412753 | 0.23830470 | 0.037517558 |
| D_G：只修未来端点 | 0.009322237 | 0.23767414 | 0.037462357 |
| G_G：两端同时修正 | 0.009307399 | 0.23722084 | 0.037428203 |

固定 Oracle 端点后再修历史采样，均值 ΔMSE=−1.48e-5、ΔLPIPS=−0.000453，且三例方向一致。固定预测端点再修历史，均值 ΔMSE=+2.91e-5，三例均变差。

两端同时修正的均值较好，但不代表每例都在全部指标上优于原 TAU；尤其不能用这 3 个有目的挑选的片段宣称稳定提升。实际预算不匹配的原始效应也保留，主要条件性 MSE 关系没有反转。

## 5. 对下一步架构的约束

当前不应只做“更好的历史特征提取”，也不应只看未来 UV ADE。冻结原型需要同时保证历史外观属于正确轨迹、未来位置足够可靠，再允许受限修改。

下一步仍可保持低成本：

1. 先用可观测的历史前后向一致性、局部外观一致性和可见性检查减少错误历史采样，不使用 GT 替代部署输入。
2. 将未来端点的不确定性与历史记忆可靠性分开；历史 confidence 不能直接当作未来可见性或写入正确率。
3. 对“不可靠端点 + 高外观差异”的候选保留 keep，先在开发集检验误接受和覆盖率，不在旧验证集放宽阈值。
4. 如果继续做冻结局部搜索，应同时报告两端一致性、实际 RGB 修改量与最终多指标，而不是只用特征 loss 下降证明成功。

这些是由诊断得到的下一步约束，本轮没有实现新的部署策略、改变评分器门槛或启动正式训练。
