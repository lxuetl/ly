# Oracle 轨迹与局部评分器低成本诊断

日期：2026-10-18。服务器：westb:34220。没有启动正式训练，没有优化器步骤，没有改动已训练模型或部署策略。

## 结论

当前证据不支持“Oracle 轨迹本身没有价值”。更准确的判断是：原型的可见性接口不完整；历史 encoder 特征到预测 latent 的转换尚未对齐；注意力接近时间均匀聚合；稀疏且受限的特征残差只有很小的图像影响。修正可见性本身不足以挽救当前模型。

局部评分器的全 keep 不是执行错误：收益下界与 MSE 风险上界的门槛没有交集。预测误差、输入分布偏移与少量校准视频上的最坏候选残差共同产生过大的统一余量。输出标准化版本又出现收益预测接近常数的问题，不能简单归结为“阈值设得太严”。

## 诊断范围和证据边界

- 轨迹：复用现有 12 个开发集原始视频，每视频一个片段；没有重选样本，没有用测试集，没有新训练。
- 评分器：只读现有 fit64/dev12/cal12/evaluation40 缓存和模型；评价集统计用于解释已观察现象，不用于修改阈值或选择新策略。
- 未来真实 UV、可见性、RGB 编码特征以及真实误差梯度只用于标注依赖的诊断干预，不能部署。
- 所有 MSE 是视频等权平均。诊断只检查 MSE 方向，不代替 LPIPS/时序指标的完整重新评测。开发集出现小幅改善不等于解决了此前评价集上的无收益现象。
- 原始结果及缓存保持不变，新增服务器结果目录为 `/root/autodl-fs/d4rt_training/interface_diagnostics_20261018`。

## 1. UV、身份映射和可见性

检查了 `cache_d4rt_forecasting._select_queries`、`VideoForecastDataset`、源数据 loader 和原型缓存构建代码。

`query_ids` 指向源数据同一批轨迹的索引，D4RT 查询点由这些轨迹的第 0 帧位置生成。重建历史 top-k 后，缓存历史 UV 与重建 UV 顺序完全一致；源数据未来 UV 归一化并裁剪后，与缓存 Oracle UV 一致。这些检查没有发现点 ID 乱序或 x/y 互换。

在既有 12 个开发视频上（视频内均值再视频等权）：

| 接口指标 | 结果 |
|---|---:|
| 历史 D4RT UV 对真实轨迹误差，128 分辨率像素单位 | 2.90 px |
| 第 0 帧误差 | 0.65 px |
| 未来 UV 越界/非有限占比 | 14.84% |
| 未来真实不可见占比 | 26.48% |
| 未来真实可见且在图内 | 73.32% |
| 原写入权重落在未来不可见或图外点上的比例 | 26.69% |
| D4RT full-clip teacher 的 future_valid 与真实可见且图内掩码不一致 | 9.51% |
| 历史 D4RT 有效但真实不可见/图外比例 | 5.19% |

注意：`future_valid` 来自 D4RT 全片段推理，不等于真实可见性；历史 confidence 经 `conf/(1+conf)` 转换，也不等于未来可见概率。不能将其中任何一个直接宣称为已校准的未来遮挡概率。

原 Oracle 缺失的接口是：只替换未来位置，仍使用 D4RT 历史采样位置/历史掩码；真实未来 UV 在 Dataset 中被裁到 [0,1]；未来可见性没有控制写入。图外点可能被错误写到边缘。

同一已有 Oracle 模型、同一冻结 TAU 的干预结果：

| 干预 | MSE |
|---|---:|
| TAU | 0.0112415821 |
| 原 Oracle | 0.0112400679 |
| 原历史特征 + 未裁剪未来 UV + 真实未来可见且图内过滤 | 0.0112400620 |
| 真实历史位置/可见性采样 + 原裁剪未来 UV | 0.0112401971 |
| 真实历史采样 + 未裁剪未来 UV + 真实未来可见性 | 0.0112400511 |
| 同权重改为 confidence 加权均匀时间聚合 | 0.0112400674 |
| 同权重改为预测未来 UV | 0.0112411639 |

后三类 GT 干预是联合接口替换，尤其 GT 历史分支同时更换采样位置、掩码和置信度，不能把差异独立归因给其中一个变量。结果显示联合修正幅度极小；这说明接口必须修，但不是当前瓶颈的充分解释。GT 干预仍有分布偏移，不能将其无收益当作理论反证。

## 2. 特征传输路径：未断路，但信息利用弱

原型执行的是 `out(attention(V(历史 encoder 特征)))` 作为小残差加到未来 translator latent，而非具有对齐约束的“历史特征搬运后减去未来基准特征”。目前没有显式监督保证这两个空间的兼容性。

- 隐状态形状/skip 形状在逐视频 JSON 中保存。
- 原写入支持区仅覆盖约 24.16% 的低分辨率 latent 网格，平均 support 为 0.1982；这不是高分辨率运动物体覆盖率。
- latent 残差平均绝对值约 0.001530；hidden 本身平均绝对值约 1.227。
- 最终 RGB 平均绝对改变量仅 0.00008393，约是允许 0.002 图像均值预算的 4.2%。预算是上限，不是应当用满的目标。
- 每个注意力头的有效历史帧数平均 15.35/16，接近均匀；与 confidence prior 的单元素平均权重差约 0.00493。同权重均匀聚合结果几乎相同。
- 输出线性层内容项平均绝对值 0.1765，bias 0.01114，不能将结果解释成“完全由 bias 输出”。
- 清零历史特征：MSE 0.0112416123；打乱轨迹间历史特征：0.0112412650；原模型为 0.0112400679。路径依赖特征内容，也依赖轨迹对应关系，但效应很小。

### 为什么不能把真实未来 encoder 当作上界

直接替换未来 hidden 为真实未来 RGB 的 encoder 特征，MSE 是 0.0170911；仅替换 skip 为真实未来 encoder skip 是 0.0899938；两者都替换为 0.1287759，均明显差于 TAU。

这不是“真实信息有害”的结论，而是预测解码器没有被训练为未来单帧 encoder 的自编码器。两个输入空间不可直接互换。因此这些替换是兼容性探针，不能称为收益上界或据此判断几何方向失败。

在相同稀疏支持区上将历史 encoder 特征搬到未来位置做 hidden 替换，未限幅 MSE 约 0.0123074；即使使用真实未来 encoder 特征做同样稀疏替换，也约 0.0122995。加同样图像预算后约 0.0112376，几种特征来源差异很小。这进一步提示接口/表示和稀疏插值会掩盖真实轨迹与真实特征的差异，但不是对其贡献的独立因果证明。

### 冻结解码器有没有修正空间

用真实误差对输入特征求梯度，沿下降方向做一次固定平均绝对值 0.002 的输入扰动，再施加相同图像预算和像素限幅：

| 标注依赖探针 | MSE |
|---|---:|
| TAU | 0.0112415821 |
| 仅 hidden 梯度方向 | 0.0111776762 |
| 仅 skip 梯度方向 | 0.0108916404 |
| hidden 与 skip 同时 | 0.0108288797 |

没有更新模型权重。这只说明冻结解码器对输入修正有响应，不是可部署方法、泛化收益或全局最优上界。hidden/skip 维数、单位、坐标和灵敏度不同，也不能用这一表宣称改 skip 架构必然更好。

原模型残差与 MSE 梯度的平均余弦为 -0.0287：开发集平均方向略有利，但与有效下降方向对齐很弱。第一阶预测 MSE 改善约 1.55e-6，与实际小幅改善量级吻合。

## 3. 局部评分器为什么全 keep

原局部模型在 evaluation40 上有 160 个候选。真实标签显示 39/40 视频至少有一个符合既定安全改善定义的候选，但模型不知道这些标签。

校准公式与单位重新核算一致：

`预测 LPIPS gain - 0.010171674 > 0.0001`

`预测相对 MSE 变化 + 0.035851385 <= 0.01`

`预测相对时序误差变化 + 0.003861286 <= 0.01`

即预测 gain 必须超过 0.010271674；预测 MSE 变化必须低于 -2.5851%；预测时序变化必须不高于 +0.6139%。这里风险单位是相对误差比例，不是绝对 MSE。

| 门槛 | 通过候选数 /160 | 至少一个通过的视频数 /40 |
|---|---:|---:|
| 收益 | 2 | 1 |
| MSE 风险 | 20 | 10 |
| 时序风险 | 140 | 39 |
| 三者同时 | 0 | 0 |

仅取消收益约束会出现 10 个可编辑视频；仅取消 MSE 约束出现 1 个；仅取消时序约束仍是 0。以上只是归因，不是阈值修改建议。

原局部 gain 预测 MAE=0.003197，而真实候选平均 gain=0.001676，预测误差大于典型收益；gain 与真实值相关系数仅 0.226。风险预测的相对 MSE MAE=0.01164，也已大于允许的 0.01 风险阈值。能做粗排序不等于能可靠判断安全改善。

### 校准余量从哪里来

每个校准视频先在四候选上取单侧最坏残差，再用 12 视频 q90/higher。此实现选到第二大的视频残差；其后还同时要求三个头通过。这是经验保守规则，不是完整的选择后安全保证。

- 收益第二大残差来自 ADT `decoration_skeleton_seq140` 的 velocity_texture：预测 gain=0.005963，真实=-0.004209，差 0.010172。
- MSE 第二大残差来自 PointOdyssey `scene-recording-20210910-S05-S06-0-ego2-2a9a034a` 的 align_rgb：预测 MSE 变化=-2.8856%，真实=+0.6996%，低估风险 3.5851 个百分点。
- 最坏的 `seminar-h52-ego1-73f68864` 虽未单独决定 q90，但也有明显外推错误；不是删掉一个视频就能证明问题解决。

输入分布偏移与大残差同时出现：fit 全局特征最大标准化绝对值约 3.41；校准的 seminar-h52 达 8.05，40.74% 的候选×特征项超出 fit 逐维范围；上述 scene-recording 达 4.16。dev 中 seminar_g110 达 11.47。范围越界本身不证明错误原因，但支持“64 视频不足以覆盖现有输入分布，极端外推拉大校准余量”的解释。

不应事后根据评价结果删掉这些视频、放宽风险阈值或绕过校准。若增加 OOD abstain，应先独立定义该规则，再对完整政策重新校准。

### 输出标准化为什么也全 keep

既有 normalized 版本局部收益预测范围很窄：evaluation160 候选均值 0.001274、最大 0.001722，相关系数 0.061；校准后要求 gain>0.004761，没有任何候选可能通过。该版本 dev 选择 epoch1，支持收益头尚缺乏判别能力/接近常数的解释，但不能据此确定是训练时长、损失还是表示造成的。

因此数值标准化降低了部分误差，却没有解决低收益信号的可辨识性。单纯缩小 margin 会把未知风险重新放回输出，不构成解决方案。

## 4. 下一步顺序（本轮没有执行训练）

1. 先建立独立、可测试的轨迹接口：保留原始未裁剪 UV；区分 GT 可见性、D4RT 可见性与历史 confidence；严格禁止部署端使用未来 GT。没有未来可见性预测器时，应显式保持未知/保守策略，而不是复制历史 confidence 当未来可见概率。
2. 继续冻结权重，在可比较的表示空间做传输残差诊断：区分 source feature、future base feature 和 residual；同时报告支持区域误差、全图误差、像素预算与 GT/预测轨迹对照。不能把 raw encoder 直接注入未来 latent 当成正确特征上界。
3. 先检验时间选择是否真正必要，再考虑扩展注意力：当前同权重均匀几乎一样，应优先让可见历史帧、最近有效观测及遮挡片段有可解释差异。
4. 评分器先做开发/校准集上的 OOD 与按动作残差诊断、可靠性评估，考虑小模型/动作条件不确定度及更充分的独立校准数据；不在现有评价集挑阈值。必须同时报告非零覆盖率和安全性，不能把 keep 的零风险当成功。
5. 只有接口诊断显示真实轨迹优势能稳定进入最终预测、且评分器不靠拒绝一切获得安全时，再讨论小规模拟合或正式训练。
